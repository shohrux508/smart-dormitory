# 📡 SMART-DORMITORY — specs_v3.md
## Desk Light Control / Reliability Layer

### Version
v3 (Reliability Extension - Finalized)

### Goal
Повысить устойчивость системы к обрывам соединений и обеспечить предсказуемое восстановление состояния устройств, используя сервер как единственный источник истины.

---

## What we DO

### 1. Server-side State Authority & Simplified Reconnect
- **Сервер — единственный источник истины (Single Source of Truth).**
- При подключении (`device_hello`) сервер **игнорирует** текущее состояние, о котором сообщает устройство (если сообщает).
- Сервер **сразу** в ответ на рукопожатие отправляет текущее состояние, хранящееся в памяти сервера.
- **Поток:**
  1. Device → `{"type": "hello", ...}`
  2. Server → `{"type": "sync_state", "state": "ON"}` (сразу, без 200 OK)
  3. Device → Применяет состояние физически.

### 2. Heartbeat / Ping (Strict Timing)
- Сервер контролирует здоровье соединения.
- **Интервал Ping:** Каждые **5 секунд** сервер отправляет `{"type": "ping"}`.
- **Таймаут:** Если сервер не получает `{"type": "pong"}` в течение **15 секунд** (3 пропущенных пинга), соединение принудительно закрывается.
- Устройство помечается как `offline`.

### 3. API Behavior (Optimistic Updates)
- `POST /api/devices/{id}/turn_on`
- Если устройство `offline`:
  - Сервер обновляет состояние в памяти (`state: "ON"`).
  - Возвращает **200 OK**.
  - Команда будет синхронизирована при следующем подключении устройства (через `sync_state`).
- `GET /api/devices/`
  - Возвращает поле `status`: `"online" | "offline"`.

---

## What we DO NOT do
- ❌ Нет базы данных (храним в памяти).
- ❌ Нет истории состояний.
- ❌ Нет очередей сообщений (только последнее актуальное состояние).
- ❌ Нет подтверждений доставки команд (ACK) — полагаемся на TCP и Heartbeat.

## Protocol Definitions

### Messages

**Device → Server**
```json
// Handshake
{
  "type": "hello",
  "device_id": "esp32_01",
  "client_type": "device" 
}

// Heartbeat Response
{"type": "pong"}
```

**Server → Device**
```json
// Sync State (сразу после Hello или при изменении через API)
{"type": "sync_state", "state": "ON"} // "ON" | "OFF"

// Heartbeat Request
{"type": "ping"}
```

### JSON Response Format (API)
`GET /api/devices/`

```json
[
  {
    "device_id": "esp32_01",
    "state": "ON",
    "status": "online" // or "offline"
  }
]
```

## Edge Cases Handling

1.  **Устройство переподключилось (свет моргнул):**
    *   Старое соединение разрывается.
    *   Новое соединение принимается.
    *   Сервер пушит сохраненное состояние (лампа возвращается в режим, который был на сервере).

2.  **API запрос во время обрыва:**
    *   Пользователь нажал "ВКЛ".
    *   Сервер обновил память в "ВКЛ".
    *   API вернул 200 OK.
    *   Лампа подключилась через минуту -> получила "ВКЛ".

3.  **Зомби-соединение (кабель выдернули):**
    *   Сервер шлет Ping.
    *   Нет Pong 15 сек.
    *   Статус меняется на Offline.

## Constraints
- Python 3.11
- FastAPI
- WebSockets
- In-memory storage only
- Один процесс сервера

## Done When
- [ ] Устройство получает актуальное состояние сразу при подключении.
- [ ] Сервер детектит разрыв соединения за ~15 секунд.
- [ ] API позволяет управлять устройством даже если оно offline (оптимистично).
- [ ] Тесты покрывают сценарии реконнекта и таймаутов.
