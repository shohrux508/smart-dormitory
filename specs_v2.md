# 🤖 Dormitory Bot — specs_v2.md

## 1. Цель (Этап 2)

Расширить MVP_V1, добавив:

- персональные **таски для каждого участника**
- **одного администратора**
- **ежедневное автоматическое сообщение** в группу

Бот по-прежнему:
- работает в одной группе
- поддерживает максимум 4 участника

---

## 2. Основные изменения относительно v1

Добавляется:
- роль администратора
- хранение тасков внутри пользователей
- ежедневная рассылка сообщения в фиксированное время

Не добавляется:
- подтверждения выполнения
- сложные роли или права

---

## 3. Роли

### Администратор
- Ровно **один**
- Определяется:
   - ID прописывается в `.env` 

### Обычные пользователи
- До 4 человек
- Не могут управлять тасками

---

## 4. Таски

### Общая логика
- У каждого пользователя **один текстовый таск**
- Таск хранится **внутри пользователя**
- Формат таска — обычная строка (без структуры)

Пример:
"Уборка комнаты"
"Вынос мусора"
"Проветривание"


## 5. Команды администратора

### `/settask @username текст_таска`
- Доступна **только админу**
- Назначает таск конкретному пользователю
- Перезаписывает предыдущий таск, если он был

Пример:
/settask @ivan Уборка комнаты




---

## 6. Команды пользователей

### `/status`
- Показывает:
  - список пользователей
  - их таски (или "не задан")



---

## 7. Ежедневное сообщение

### Поведение
- Один раз в день
- В **фиксированное время** (например, 09:00)
- Сообщение отправляется **в группу**

### Формат сообщения

📅 <День недели>, <число>
👤 <Имя участника>
📝 <Таск>


Пример:
📅 Понедельник, 29
👤 Иван
📝 Уборка комнаты


### Правила
- Если у пользователя нет таска:
📝 Таск не назначен


- Пользователь для сообщения:
   - Детерминированный выбор: `(день_года % кол_во_юзеров)`
   - Гарантирует "честную" очередь без сохранения состояния

*(На этом этапе допускается самый простой вариант: один пользователь в день)*

---

## 8. Хранение данных (обновление)

Пример структуры пользователя:

{
"telegram_id": 123456,
"username": "ivan",
"joined_at": "2026-01-29T10:00",
"task": "Уборка комнаты"
}

10. Ограничения и упрощения
Без учёта часовых поясов

Без пропусков дней

Без подтверждений выполнения

Без истории

11. Definition of Done (v2)
Этап 2 считается завершённым, когда:

Назначен один администратор

Админ может задавать таски пользователям

Таски сохраняются в БД

Бот ежедневно отправляет сообщение в группу

Сообщение соответствует заданному формату
