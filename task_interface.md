# Техническое задание: Улучшение Web Dashboard

Этот файл содержит список задач (тикетов) для реализации второй версии панели управления Smart Dormitory.

## 1. Функциональные улучшения

### Тикет 1.1: Группировка устройств по комнатам
**Статус:** `К выполнению`
**Описание:**
Разделить единую сетку устройств на семантические зоны (комнаты).
**Требования:**
- Сгруппировать устройства по полю `room` из API (или `DeviceMeta` в БД).
- Для каждой комнаты создать отдельный визуальный блок с заголовком.
- Сохранить адаптивность сетки (Grid Layout).

### Тикет 1.2: Редактирование метаданных
**Статус:** `К выполнению`
**Описание:**
Реализовать интерфейс для изменения имени устройства и его комнаты.
**Требования:**
- Добавить кнопку "Настройки" (icon: cog) на карточку устройства.
- Реализовать модальное окно с формой:
  - Название (Input Text)
  - Комната (Input Text / Select)
- Реализовать отправку PATCH запроса на сервер для обновления данных.

### Тикет 1.3: Типизация иконок
**Статус:** `К выполнению`
**Описание:**
Отображать специфичные иконки в зависимости от типа устройства.
**Требования:**
- Использовать поле `type` из объекта устройства.
- Реализовать маппинг:
  - Light -> 💡
  - Socket -> 🔌
  - Switch -> 🔘
  - Sensor -> 🌡️

## 2. UX Интерфейс

### Тикет 2.1: Toast-уведомления
**Статус:** `К выполнению`
**Описание:**
Добавить систему всплывающих уведомлений для обратной связи.
**Требования:**
- Покзывать уведомления при: успехе действия, ошибке сети, новом подключении.
- Автоматическое скрытие через 3-5 секунд.
- Позиционирование: снизу-справа или сверху-по центру.

### Тикет 2.2: Доработка Optimistic UI
**Статус:** `К выполнению`
**Описание:**
Улучшить визуальный отклик интерфейса.
**Требования:**
- Мгновенное переключение состояния (ON/OFF) в UI при клике.
- Автоматический откат состояния с уведомлением (Toast) при ошибке API.
- Убрать "дергание" интерфейса при обновлении списка.

### Тикет 2.3: Графики (Dashboard v2.1)
**Статус:** `Backlog`
**Описание:**
Добавить мини-аналитику.
**Идея:**
- Sparkline-график активности устройства за последние 24 часа прямо на карточке.

## 3. Техническая Архитектура

### Тикет 3.1: Миграция на WebSockets
**Статус:** `К выполнению` (High Priority)
**Описание:**
Заменить метод Long Polling (запросы каждые 2 сек) на WebSockets.
**План реализации:**
1.  **Backend (FastAPI):**
    - Создать WebSocket Endpoint `/ws`.
    - Реализовать менеджер соединений для Broadcast-рассылки обновлений.
2.  **Frontend (Vanilla JS):**
    - Подключится к WS.
    - Слушать события изменения состояния и обновлять DOM без перезагрузки.
